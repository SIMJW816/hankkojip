# 한꼬집 Flutter 앱

기존 반응형 웹을 유지하면서 iOS·Android에서 같은 Flask API를 사용하는 별도 앱입니다. 런타임 외부 패키지 없이 Flutter와 Dart의 HTTP 클라이언트를 사용합니다.

## 기능

- 홈 요약, 재료 슬롯 이름·사용 가능 상태 수정
- CUSTOM 배합 입력, AI 배합 생성
- AI 대화 탭: 자유로운 음식 추천·질문·배합 수정, 배합 확인·저장·계량 화면 연결
- 레시피 저장·수정·삭제·즐겨찾기
- 재료별 목표 중량 확인과 명시적 최종 승인
- 모의·실계량 진행, 중단, 제조 이력과 재료별 측정값
- 종료된 제조 이력 삭제(확인창 제공), 이력의 목표 중량을 내 레시피로 저장
- 서버 주소 설정, 통신 오류 표시와 재연결

기본 모드는 모의 계량입니다. 실제 계량은 [Pi·Arduino 연동 안내](../HARDWARE_INTEGRATION.md)에 따라 서버와 보드를 준비한 뒤, 앱의 **서버 연결**에서 Pi의 주소와 **실계량 제어 키**를 입력합니다. 앱은 시작 요청과 장치 준비 상태를 Flask에서 확인하고, 제조 이력에서 모의 값과 실측값을 구분합니다. 화면을 닫아도 장치 제어는 서버와 Arduino에서 계속되며 앱을 다시 열면 결과를 조회합니다.

## iPhone 시연

Flutter SDK(Dart 3.13.5 이상 포함), Xcode와 iOS 개발 환경이 필요합니다.

1. 저장소 루트에서 서버를 실행합니다. 아래 명령은 모의 계량 시연용 Wi-Fi에서 사용합니다.

   ```sh
   DEVICE_MODE=demo HOST=0.0.0.0 .venv/bin/python app.py
   ```

2. iPhone과 Mac을 같은 Wi-Fi에 연결합니다. Mac 시스템 설정의 네트워크에서 로컬 IP를 확인합니다.
3. iPhone을 Mac에 연결하고 신뢰 및 개발자 모드를 설정합니다. Xcode에서 `ios/Runner.xcworkspace`를 열고 Runner의 Signing & Capabilities에서 본인 Team을 선택합니다. 필요하면 Bundle Identifier를 본인에게 고유한 값으로 변경합니다.
4. 앱 디렉터리에서 실행합니다.

   ```sh
   cd mobile
   flutter pub get
   flutter devices
   flutter run -d <아이폰-device-id> --dart-define=API_BASE_URL=http://192.168.0.10:8000
   ```

   주소는 실제 Mac의 IP로 바꿉니다. 앱 우측 상단 설정에서도 서버 주소를 바꿀 수 있습니다. 설정에서 바꾼 주소는 앱 종료 후 유지되지 않으므로 시연에는 `--dart-define`을 권장합니다. 로컬 네트워크 접근 권한을 허용하고 Mac 방화벽의 서버 접근도 확인합니다.

- iOS 시뮬레이터: 기본 주소 `http://127.0.0.1:8000` 사용 가능
- iPhone 실기기: `127.0.0.1`은 iPhone 자체이므로 Mac의 IP 사용
- 로컬 HTTP 연결을 위한 iOS 로컬 네트워크 사용 설명 및 ATS 로컬 네트워크 설정 포함

## Android

같은 Dart 코드를 사용합니다. Android SDK·에뮬레이터 또는 USB 디버깅한 기기가 필요합니다.

```sh
flutter run -d <안드로이드-device-id> --dart-define=API_BASE_URL=http://192.168.0.10:8000
```

Android 기본 에뮬레이터에서는 Mac 서버 주소로 `http://10.0.2.2:8000`을 사용합니다. 인터넷 권한은 포함되어 있고 로컬 HTTP는 debug/profile 빌드에서만 허용합니다. release 배포에는 HTTPS 서버 주소와 별도의 서명 설정이 필요합니다.

## 검증

```sh
flutter analyze
flutter test --concurrency=1
flutter build ios --debug --no-codesign
```

테스트는 서버 주소·JSON·오류 전달, 다양한 화면 크기의 배합 입력, 슬롯 변경 후 과거 배합 거부와 AI 대화 상태를 확인합니다. 실제 iPhone 서명·설치와 서버 통신, 로컬 네트워크 권한은 실기기에서 별도 확인해야 합니다.

승인창 안의 재시도는 동일한 요청 키를 사용합니다. 통신 오류 시 창을 닫고 새 승인을 하기 전에 계량·이력에서 기존 작업 여부를 확인하세요. 슬롯 revision은 저장 시 서버에서 다시 검증하며 오래된 레시피를 현재 재료로 자동 대체하지 않습니다.

## AI 배합 시연

서버 API 키·모델·SDK 설치는 [루트 README](../README.md#ai-api-설정)를 따르세요. 서버 루트 `.env`에 키와 모델을 저장하면 웹·앱 모두 같은 설정을 사용합니다. 변경 후 서버를 재시작하세요. 앱에 API 키를 입력하지 않습니다.

하단 AI 대화에서 `오늘 뭐 먹지?`를 선택하거나 자유롭게 음식·인분·취향을 입력합니다. 음식 추천을 선택하고 양념 배합을 제안받은 뒤 `덜 짜게 해줘`처럼 후속 요청을 보낼 수 있습니다. 결과 설명과 부족 재료를 표시하고 배합이 있는 경우에만 확인·저장·계량으로 이동합니다.

대화는 탭 전환 시 유지되지만 앱 종료나 새 대화 시 초기화되며 웹과 동기화되지 않습니다. 서버 주소가 바뀌면 이전 서버의 대화는 초기화됩니다. 이전 배합의 슬롯이 변경되거나 부족해지면 새 대화에서 현재 재료로 다시 요청합니다.

직접 배합 편집 화면에서도 AI 제안을 받을 수 있습니다. AI 응답의 슬롯 revision을 보존해 저장·제조 때 현재 슬롯과 다시 검증합니다. 실제 AI 결과는 `AI`, 과거 고정 예시는 `DEMO`로 구분합니다. AI 대화·배합 요청의 클라이언트 대기 시간은 45초이며 나머지 요청은 12초입니다.
